## Platform

web

## Stack

Delegated, then confirmed by the team: Python 3 standard library only (simulation engine, tests, HTTP server) and a vanilla HTML/CSS/JS dashboard with hand-drawn SVG charts. No npm or pip installs, no CDN, no build step. Starts with one command (`python3 gridpact.py`) and must run fully offline because venue Wi-Fi is unreliable.

## Users

- **Hackathon judges (AIML department, BMSCE, Build Beyond '26).** They watch a live demo on a laptop at the table, lean in, ask hard questions, and need to see within a minute that the agents negotiate, that hard limits hold, and that GridPact beats the baselines.
- **Team Straw Hats (Team 41).** They drive the demo, inject events live, and must be able to explain every number on screen.
- **Notional end user (framing, not a real deployment):** a city crisis-operations officer watching utilities share scarce power during a disaster.

## Product Purpose

GridPact is a decentralized power-sharing simulator for disasters. One autonomous agent represents each city utility (Hospital, Water Pumping, Emergency Services, Telecom, and more by config). Every 15 simulated minutes the agents bid, concede and agree on a split of a fluctuating power supply. A neutral validator only enforces physical limits and commits each step atomically. Success means: zero capacity violations, no inconsistent state, deterministic replay from a seed, and lower total damage than equal-split, proportional and strict-priority baselines.

## Positioning

Allocation emerges from negotiation between agents with private state (reserves, damage, fairness credits), not from a central optimizer. The validator never decides who gets what. Fairness credits earned by conceding prevent starvation, which strict priority cannot do.

## Operating Context

- Demo flow: choose scenario and seed, play / pause / step, change speed, inject events ("Substation 2 fails: -30% supply") mid-run, then open the results view comparing GridPact to baselines.
- Judges question the team using the docs (ARCHITECTURE, DECISIONS, ALGORITHM, JUDGE_QA, RESULTS).
- PS 1.1 of the hackathon is the official problem statement.

## Capabilities and Constraints

- Hard guarantees enforced in code and proven by tests: zero capacity violations, atomic commit or rollback, determinism given a seed.
- Scenarios and agents are data files, not hard-coded. At least 3 disaster scenarios plus a 20+ agent stress scenario.
- Optional LLM narration is off by default behind an env flag; the core never depends on it.
- Rule: no fake numbers. Every number shown must come from a real run.

## Brand Commitments

- Name: GridPact. Team: Straw Hats (Team 41).
- Requested tone: a crisis operations control room. Dark, calm, high-contrast, data-dense but readable, serious rather than playful.

## Evidence on Hand

All metrics come from the simulator itself (RESULTS.md is generated by script). No testimonials, real utility data or deployments exist; none may be implied.

## Product Principles

1. Correctness over features: guarantees and tests are never cut.
2. Every number on screen is traceable to a real run and explainable by the team.
3. Show the negotiation, not just the outcome: the log must read as agents reasoning.
4. Calm under crisis: status is legible at a glance; alarm is reserved for real failures.

## Accessibility & Inclusion

Viewed on a laptop at arm's length: body text no smaller than 13px, WCAG AA contrast, status never conveyed by color alone (always paired with a label).
